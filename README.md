# coding-mcp

Stdio MCP-сервер для файлов одной задачи. Процесс читает и создаёт документы, картинки и таблицы только внутри каталога `MCP_USER_WORKDIR`.

Сервер ставится в образ worker и поднимается на задачу так же, как filesystem и fetch. Отдельный порт ему не нужен. Список файлов остаётся у filesystem MCP, сеть — у fetch, Диск Bitrix — у bx-mcp.

## Инструменты

В `tools/list` ровно эти двенадцать имён.

| Инструмент | Вход | Результат |
|---|---|---|
| `read_pdf` | `path` | Текст по страницам. Страница без текстового слоя помечена `[нет текстового слоя]`. |
| `read_docx` | `path` | Абзацы и таблицы. Строка стиля Heading приходит как `# Заголовок`. Картинки пропускаются. |
| `write_docx` | `path`, `text` | DOCX. `# `, `## ` и `### ` в начале строки — заголовки, остальные непустые строки — абзацы. |
| `read_xlsx` | `path`, `sheet?` | Листы через табуляцию. Формула возвращается текстом, значение в Excel не пересчитывается. |
| `write_xlsx` | `path`, `content` | XLSX из объекта ниже. Повторная запись заменяет файл. Формулы сохраняются текстом. |
| `read_xls` | `path`, `sheet?` | Чтение старого XLS. Записи XLS нет: новый файл сохраняйте как xlsx. |
| `read_image` | `path` | PNG, JPEG, GIF, WEBP или BMP: формат, режим, размер и сама картинка, если файл не больше 2 МиБ. |
| `write_image` | `path`, `spec` | Новая картинка или копия `source` в формате пути. Повторная запись заменяет файл. |
| `read_table` | `path`, `sheet?`, `header?` | CSV, TSV, XLSX или XLS через pandas: размер, типы, пропуски и первые 30 строк. |
| `analyze_table` | `path`, `spec?`, `sheet?`, `header?` | Пропуски, describe, value_counts, корреляция, groupby. |
| `calculate_table` | `path`, `operations`, `sheet?`, `header?`, `output?` | Шаги `filter`, `derive`, `sort`, `select`, `aggregate`, `rename`, `fillna`, `dropna`, `head`. `output` создаёт CSV, TSV или XLSX. |
| `write_table` | `path`, `content` | Новый CSV, TSV или XLSX из `columns` и `rows`. Повторная запись заменяет файл. |

Пути относительные: `report.pdf`, `out/table.xlsx`. Абсолютный путь принимается только если после разрешения он остаётся внутри корня.

Пример `content` для `write_xlsx`:

```json
{
  "sheets": [
    {
      "name": "Лист1",
      "rows": [["Имя", "Сумма"], ["Анна", 2], ["Борис", "=SUM(B2:B2)"]]
    }
  ]
}
```

Допустима и JSON-строка того же вида. Ячейка — строка, число, `true`/`false` или `null`.

`write_xlsx` оставляет формулу строкой. `read_xlsx` тоже возвращает формулу текстом и значение не пересчитывает. `write_table` и `calculate_table` записывают уже посчитанные значения через pandas. Объекты `content`, `spec` и список `operations` можно передать и JSON-строкой.

### Таблицы

`write_table` создаёт файл по расширению: `.csv` с запятой, `.tsv` с табуляцией, `.xlsx` через openpyxl. Текст пишется в UTF-8 с BOM. Короткая строка дополняется пустыми ячейками. Повторный вызов заменяет файл.

```json
{
  "columns": ["Имя", "Сумма"],
  "rows": [["Анна", 2], ["Борис", 3]]
}
```

Несколько листов есть только у XLSX. У каждого листа свои `name`, `columns` и `rows`. Имя листа — до 31 символа, без `: \ / ? * [ ]`. В CSV и TSV лист один.

`read_table` по умолчанию считает первую строку заголовком. `header: false` оставляет её данными, столбцы тогда называются `0`, `1`, `2`. `sheet` задаётся только для Excel; без него читается первый лист, остальные имена перечисляются в ответе. Ответ содержит число строк и столбцов, тип и число пропусков каждого столбца и первые 30 строк. Лишние строки и столбцы в ответ не входят, в тексте есть пометка.

CSV читается в кодировке UTF-8, затем CP1251. Если в первой строке точек с запятой больше, чем запятых, разделитель — `;`, а десятичный знак — запятая. TSV всегда разделён табуляцией.

`analyze_table` без `spec` считает пропуски, describe по числовым столбцам и value_counts текстовых столбцов, у которых не больше 30 разных значений (не больше пяти таких столбцов). Явный `spec` включает только перечисленные поля:

```json
{
  "missing": true,
  "describe": true,
  "value_counts": ["region"],
  "corr": true,
  "groupby": {"by": ["region"], "agg": {"amount": ["sum", "mean"]}}
}
```

`value_counts` показывает не больше 20 значений. В ответе groupby — не больше 30 групп.

`calculate_table` применяет шаги по порядку. `output` — относительный путь `.csv`, `.tsv` или `.xlsx`; без него результат только в тексте ответа. Выражение `derive` считает арифметику по столбцам: числа, скобки, `+ - * / // % **`, а также `abs` и `round`. Имя столбца в выражении — идентификатор без пробелов. Степень — целое от 0 до 6. Атрибуты, индексы и любые другие вызовы отклоняются.

| `op` | Поля |
|---|---|
| `filter` | `column`, `cmp`, `value` |
| `derive` | `column`, `expr` |
| `sort` | `column` или `columns`, `ascending` |
| `select` | `columns` |
| `aggregate` | `by`, `agg` |
| `rename` | `columns`: объект старое имя → новое |
| `fillna` | `value`, необязательный `column` |
| `dropna` | необязательные `columns`, `how`: `any` или `all` |
| `head` | `n` |

`cmp`: `eq`, `ne`, `gt`, `ge`, `lt`, `le`, `contains`, `not_contains`, `empty`, `not_empty`. Для `gt`/`ge`/`lt`/`le` и для агрегаций, кроме `count`, столбец должен быть числовым. Агрегация: `sum`, `mean`, `min`, `max`, `count`, `median`, `nunique`.

```json
[
  {"op": "derive", "column": "vat", "expr": "amount * 0.2"},
  {"op": "filter", "column": "vat", "cmp": "gt", "value": 1},
  {"op": "aggregate", "by": ["region"], "agg": {"vat": "sum", "amount": ["sum", "mean"]}}
]
```

### Картинки

`read_image` проверяет, что содержимое совпадает с расширением, и возвращает формат, режим, размер в пикселях и число кадров, если их больше одного. Файл не больше 2 МиБ прикладывается к ответу. Более крупный файл остаётся в рабочей директории, в ответе только описание.

`write_image` берёт формат из пути: `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.bmp`. Без `source` нужны `width` и `height`. Фон по умолчанию `#FFFFFF`. Список `items` может быть пустым.

```json
{
  "width": 640,
  "height": 360,
  "background": "#FFFFFF",
  "items": [
    {"kind": "rectangle", "x": 24, "y": 24, "width": 280, "height": 160, "fill": "#2255AA"},
    {"kind": "text", "x": 40, "y": 40, "text": "Отчёт", "fill": "#FFFFFF", "size": 32},
    {"kind": "bars", "x": 320, "y": 40, "width": 280, "height": 200, "values": [2, 5, 3], "labels": ["Анна", "Борис", "Вера"], "fill": "#336699"}
  ]
}
```

| `kind` | Поля |
|---|---|
| `rectangle`, `ellipse` | `x`, `y`, `width`, `height`, `fill`, `outline`, `stroke` |
| `line` | `x1`, `y1`, `x2`, `y2`, `fill`, `stroke` |
| `text` | `x`, `y`, `text`, `fill`, `size` от 8 до 200, по умолчанию 24 |
| `bars` | `x`, `y`, `width`, `height`, `values`, `labels`, `fill` |

Цвет — `#RGB`, `#RRGGBB`, `#RRGGBBAA` или имя `white`, `black`, `red`, `green`, `blue`, `gray`, `transparent`. JPEG и BMP не хранят прозрачность: такие пиксели ложатся на белый фон. У JPEG и WEBP поле `quality` от 30 до 95, по умолчанию 90.

`source` — путь к картинке внутри рабочей директории. Оба размера задают точный холст, один размер сохраняет пропорции. Поверх копии можно нарисовать `items`. Текст вне латинского алфавита берёт системный шрифт: Arial, Segoe UI, DejaVu, Liberation или FreeSans. Если такого шрифта нет, вызов с таким текстом отклоняется.

Старые `.doc`, `.ppt` и презентации `.pptx` этот сервер не обрабатывает. PDF и старый XLS только читаются.

## Граница каталога

Корень — разрешённый путь `MCP_USER_WORKDIR` или `--root`. Каталог должен существовать. После старта процесс делает его текущим каталогом.

Каждый путь проходит `resolve`, затем проверяется, что общий префикс с корнем совпадает с корнем. Отклоняются `..`, соседний каталог с тем же префиксом (`work-evil` рядом с `work`), symlink наружу и поток NTFS (`file.xlsx:stream`). В ответ модели не попадает абсолютный путь хоста: в тексте успеха только путь относительно корня.

Это граница внутри процесса. Дочерний процесс всё ещё видит mount контейнера worker, поэтому в образ не входит запуск произвольного кода. Код сервера не открывает сеть. Пакет `mcp` при этом тянет свой HTTP-стек (`httpx`, `starlette`, `uvicorn`): SDK поставляется одним дистрибутивом, отдельно stdio-часть не ставится.

Перед `run` из окружения удаляются переменные, в имени которых есть `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD`, `WEBHOOK`, `_KEY`, `_DSN` или `_PAT`. Worker всё равно должен передавать узкий `env`, а не копию своего окружения: список выше не заменяет allowlist при spawn.

## Лимиты одного вызова

Значения зафиксированы в `coding_mcp/limits.py`.

| Лимит | Значение |
|---|---|
| Размер файла | 20 МиБ |
| Сумма несжатых данных docx/xlsx | 80 МиБ |
| Текст ответа | 80 000 символов |
| Текст или JSON на запись | 1 000 000 символов |
| Длина ячейки | 2 000 символов |
| Листы | 10 |
| Строки на лист | 2 000 |
| Столбцы | 40 |
| Страницы PDF | 50 |
| Сторона картинки | 8 000 пикселей |
| Пиксели картинки | 16 000 000, с учётом кадров |
| Картинка в ответе | 2 МиБ, выше — только описание |
| Фигуры на картинке | 200 |
| Строки предпросмотра таблицы | 30 |
| Операции calculate_table | 30 |
| Группы value_counts | 20 |
| Длина выражения | 500 символов |
| Время вызова | 20 секунд |

При чтении лишние строки, листы, столбцы и страницы не попадают в ответ, в конце есть пометка. Картинка больше 2 МиБ в ответ не вкладывается. При записи превышение лимита отклоняется, и файл не создаётся. По истечении 20 секунд tool возвращает ошибку. Сам разбор при этом может ещё занимать поток до завершения процесса задачи: worker должен завершать этот процесс вместе с задачей.

## Зависимости

Рабочий набор: `mcp` (линия 1.x), `pypdf`, `python-docx`, `openpyxl`, `xlrd`, `pillow`, `pandas`. Версии и хеши лежат в `uv.lock`.

SDK закреплён как `mcp>=1.28,<2`. Вторая мажорная версия тянет OpenTelemetry и другой HTTP-стек, которые stdio-серверу не нужны. Протокол при `initialize` согласуется с клиентом worker, включая уже стоящий fetch MCP на SDK 1.x.

`pypdf`, `python-docx`, `openpyxl`, `xlrd`, `pillow` и `pandas` импортируются внутри tool, а не при старте процесса. В образ они уже установлены. На этой машине разработки процесс ответил на `initialize` за 1,5–2,1 с: почти всё время уходит на импорт SDK. В контейнере worker цифра будет другой. Первое открытие xlsx дополнительно загружает `openpyxl`, первый расчёт таблицы — `pandas`.

`pytest` и `xlwt` стоят только в группе `dev`. `xlwt` нужен тестам, чтобы собрать старый xls. В образ worker они не входят.

Пакеты ставятся при сборке образа. В команде spawn нет `uvx` и `pip install`.

## Сборка в образ worker

Каталог этого репозитория копируется в контекст сборки worker. Локальный `.venv` копировать нельзя: он собран под ОС машины разработки. В контекст входят исходники, `pyproject.toml` и `uv.lock`.

Если контекстом сборки служит этот каталог, `.dockerignore` оставляет за его пределами `.venv/`, `__pycache__/`, `.pytest_cache/`, `*.egg-info` и `tests/`. `uv.lock` в образ входит.

```dockerfile
COPY coding_mcp /tmp/coding_mcp
RUN uv sync --frozen --no-dev --project /tmp/coding_mcp
```

Команда процесса — интерпретатор из появившегося `.venv`, не системный Python и не `uv run` на каждую задачу:

```text
/tmp/coding_mcp/.venv/bin/python -m coding_mcp
```

На Windows при локальной проверке тот же модуль запускается через `python -m coding_mcp`.

Фрагмент `mcp-servers.yaml` рядом с filesystem и fetch. Подстановку `MCP_USER_WORKDIR` делает MCPManager для конкретной задачи. `env` заменяет окружение процесса, а не дополняет окружение worker.

```yaml
documents:
  transport: stdio
  command: /tmp/coding_mcp/.venv/bin/python
  args: ["-m", "coding_mcp"]
  cwd: "${MCP_USER_WORKDIR}"
  env:
    MCP_USER_WORKDIR: "${MCP_USER_WORKDIR}"
    PATH: "/tmp/coding_mcp/.venv/bin:/usr/local/bin:/usr/bin"
    LANG: "C.UTF-8"
    PYTHONUNBUFFERED: "1"
    PYTHONDONTWRITEBYTECODE: "1"
    PYTHONNOUSERSITE: "1"
```

Stdout занят протоколом MCP. Журнал пишется в stderr одной строкой `coding-mcp stdio готов`. Без `--root` и без `MCP_USER_WORKDIR` процесс завершается с кодом 2 и ничего не пишет в stdout.

## Локальный запуск

Нужен Python 3.11 или новее и [uv](https://docs.astral.sh/uv/). Если uv не может проверить сертификат PyPI, добавьте к команде флаг `--system-certs`.

```powershell
uv sync --frozen --group dev
$env:MCP_USER_WORKDIR = "C:\path\to\workdir"
uv run --frozen --no-dev python -m coding_mcp
```

Процесс ждёт сообщения MCP на stdin. Для проверки списка инструментов подойдёт MCP Inspector: транспорт stdio, команда `python -m coding_mcp`, переменная `MCP_USER_WORKDIR`.

Тесты:

```powershell
uv run --frozen --group dev pytest
```

## Что остаётся соседним сервисам

- Список каталога и мелкие правки txt — filesystem MCP.
- Скачивание вложения Bitrix в workdir и upload результата — bx-mcp.
- Публичные URL — fetch MCP.
- Произвольный Python модели — не этот процесс. Pandas здесь считает только описанные шаги, без `eval` и без запуска кода. Для произвольного кода нужен отдельный запуск с одним смонтированным каталогом и без окружения worker.
